A notifier provider exposes an object with a `state` and methods that mutate it. It is the case
`act` was designed for.

## Acting on a notifier

`TestRef.notifier(provider)` is shorthand for `read(provider.notifier)`. It accepts every notifier
provider — hand-written, family or generated by `riverpod_generator`.

```dart
final counterProvider = NotifierProvider<Counter, int>(Counter.new);

class Counter extends Notifier<int> {
  @override
  int build() => 0;

  void increment() => state++;
  void decrement() => state--;
}

riverpodTest(
  'emits [0, 1, 2, 1]',
  provider: counterProvider,
  act: (ref) {
    ref.notifier(counterProvider)
      ..increment()
      ..increment()
      ..decrement();
  },
  expect: () => [0, 1, 2, 1],
);
```

`act` may be synchronous or asynchronous — it returns `FutureOr<void>` and is awaited.

<Info>
  `TestRef` exists because there is no single object to act upon that fits every target: a
  `Provider` has no notifier, a family is a provider factory, and a mutation is triggered from
  elsewhere entirely. `TestRef` is that missing handle; it wraps the container the test runs in.
</Info>

## AsyncNotifier

The observed state of an `AsyncNotifier<T>` is `AsyncValue<T>`, so `expect` speaks `AsyncValue`.

```dart
final userProvider = AsyncNotifierProvider<UserNotifier, User>(UserNotifier.new);

class UserNotifier extends AsyncNotifier<User> {
  @override
  Future<User> build() => ref.watch(userRepositoryProvider).fetchUser();

  Future<void> rename(String name) async {
    state = const AsyncLoading<User>();
    state = await AsyncValue.guard(
      () => ref.read(userRepositoryProvider).rename(name),
    );
  }
}

riverpodTest(
  'emits [loading, data, loading, data] when renaming',
  provider: userProvider,
  setUp: () {
    repository = MockUserRepository();
    when(repository.fetchUser).thenAnswer((_) async => const User('Ada'));
    when(() => repository.rename(any())).thenAnswer((_) async => const User('Grace'));
  },
  overrides: () => [userRepositoryProvider.overrideWithValue(repository)],
  act: (ref) async {
    // Wait for the initial build before mutating, otherwise the two loading
    // states collapse into one.
    await ref.read(userProvider.future);
    await ref.notifier(userProvider).rename('Grace');
  },
  expect: () => [
    isLoading,
    isData(const User('Ada')),
    isLoading,
    isData(const User('Grace')),
  ],
);
```

If you only care about what happens after the provider settles, `skip: 2` drops the initial
`loading`/`data` pair, or `fireImmediately: false` drops the very first emission.

## StreamNotifier

Identical in shape — `StreamNotifierProvider` also exposes `AsyncValue<T>`:

```dart
final ticksProvider = StreamNotifierProvider<TicksNotifier, int>(TicksNotifier.new);

class TicksNotifier extends StreamNotifier<int> {
  @override
  Stream<int> build() => Stream.fromIterable([1, 2]);

  void push(int value) => state = AsyncData(value);
}

riverpodTest(
  'emits the stream, then the pushed value',
  provider: ticksProvider,
  wait: const Duration(milliseconds: 10),
  act: (ref) => ref.notifier(ticksProvider).push(99),
  expect: () => [isLoading, isData(1), isData(2), isData(99)],
);
```

## Code-generated notifiers

Providers generated by `riverpod_generator` are notifier providers like any other, so nothing
changes:

```dart
@riverpod
class Counter extends _$Counter {
  @override
  int build() => 0;

  void increment() => state++;
}

riverpodTest(
  'increments',
  provider: counterProvider,
  act: (ref) => ref.notifier(counterProvider).increment(),
  expect: () => [0, 1],
);
```

## Reading the notifier without acting

`verify` receives the same `TestRef`, and the container is still alive when it runs — so the
notifier can be inspected after the assertions:

```dart
riverpodTest(
  'keeps the history',
  provider: counterProvider,
  act: (ref) => ref.notifier(counterProvider).increment(),
  expect: () => [0, 1],
  verify: (ref) => expect(ref.notifier(counterProvider).history, [0, 1]),
);
```

## Starting from another state

A notifier starts from whatever its `build` returns, and `overrideWithBuild` replaces that build
while keeping the notifier and its methods:

```dart
overrides: () => [counterProvider.overrideWithBuild((ref, self) => 9)],
```

See [Seeding](/seeding) for the recipe per provider type.
